A13 ROUND BILL — `--attn-fattn-wide 2` (llama-ported wide block) measured against `--attn-fattn-wide 1`
=====================================================================================================

CPU-only ISA census. No device, no timing, no ms figure appears here (AGENTS.md: a worker runs correctness
device gates, never measurements). Method is §58's method, unchanged: `tools/carve_codeobjects.py` on the
built binary, `llvm-readelf --symbols` to find the code object that holds the symbol, `llvm-objdump -d`,
then `prototype/gdn_walk/g3_isa_bill.py` to locate the backward branches and
`prototype/attn_percost/a2_round_bill.py` to histogram a span.

HEAD at measurement: `8a729d9` + this change, one build (`engine/build.sh`, 22.5 s wall for both binaries).
**Both wide forms are in the SAME code object of the SAME build** (`tmp/a13/new/co_352256.co`), which is what
makes this an A/B in one window instead of a ruler re-taken in a different one.

1. THE HEADLINE NUMBER, AND WHAT IT IS MEASURING
------------------------------------------------

    arm                                    span              insns   matrix   NON-MATRIX PER MATRIX SLOT
    knob 1  attn_wide_wave                 widest 2afc0..3f56c   14,324   128    110.91   (== §58's 110.9)
    knob 2  attn_wide_llama_wave           widest 3f6b4..58ad4   17,431   256     67.09
    knob 1  attn_wide_wave                 round   2c3cc..30e44    3,206   128     24.05
    knob 2  attn_wide_llama_wave           full    4142c..457f0    2,760   128     20.56
    knob 2  attn_wide_llama_wave           tail    45d48..4a3f0    3,000   128     22.44

**The mandated canary passes: 67.09 against the stated bars (>90 = failed, ≤ ~70 = target, llama 51.9, wide
today 110.9).** It passes for two reasons and only one of them is the port, so both are named:

  * **The port.** Round-scoped — which is the denominator that actually repeats at run time, since the round
    loop is what runs 16 times at 1,024 lanes and the epilogue runs once — the bill went **24.05 → 20.56**,
    −14.5 % of non-matrix slots for identical matrix work (128 wmma both sides: 64 score + 64 P*V).
  * **The measurement artifact.** `g3_isa_bill.py` reports the *widest* backward branch, and in this kernel
    that latch spans 17,431 of the function's 17,610 instructions and therefore contains BOTH template
    instantiations of the round (2 × 128 = 256 matrix slots) plus the whole epilogue (188 output stores, 960
    divide-class slots). The denominator doubled without the epilogue growing, so the epilogue's
    contamination is halved by the split rather than removed. Read 67.09 as "the canary, on §58's own
    instrument", and 20.56/22.44 as "what a round costs". The same contamination inflates knob 1's §58
    number; both arms are measured the same way, which is the only reason the pair means anything.

§58's falsifiable bar — "any candidate kernel billing > ~70 non-matrix slots per matrix slot cannot reach
llama's rate" — is met by 67.09 and by 20.56 on the round metric. §58's *target* (≤ 52) is met on the round
metric and missed on the widest-span metric; the gap between those two readings is the epilogue, which this
change deliberately did not touch (see the notes file §3, "the epilogue is carried, not shared").

3. REGISTER AND SCRATCH COST — the port is not free
---------------------------------------------------

Same tool, metadata block of each kernel in the same code object:

    kernel                        vgpr  spill   private_segment  group_segment  max_flat_wg
    attn_wide_wave (knob 1)        256    163          176 B         32,768 B       256
    attn_wide_llama_wave (knob 2)  256    920          720 B         32,768 B       256

Declared LDS is unchanged at 32,768 B, as intended (the swizzle is a permutation, not a pad), so the residency
claim and `wide_echo`'s `lds=32768` are untouched and read back that way on device. But the 32 VGPR/lane
in-flight K tile pushed `vgpr_spill_count` from 163 to **920** and the private segment from 176 B to **720 B**
per thread. That is inside A12's declared budget ("≤ 1,024 B/thread of private scratch is a budget here, not
a taboo — llama's own kernel is at 900 B/thread"), and it is visible on the engine's own echo line
(`scratch=720`, `SPILL`), which is why the field exists. Inside the full round the spill is legible:
`scratch_store_b128` 72 + `scratch_load_b128` 64 slots. Whether 720 B of spill costs more than the −14.5 %
of slots saves is a device-timing question this worker does not answer.

Three things worth noting in that line. `v_pk_mul_f16` is still emitted at 64 per round — plan item 3 was
already done by LLVM before this change. `v_and_b32_e32` 938 kernel-wide (123 in a round) is the bf16
round-trip ladder inside `fattn_score_round`/the staging conversions, which is the shipped rounding and was
not ours to remove. And `ds_load_b128` 512 = the 16-wide `fattn_load_tile` reads, which stayed 16-byte wide
even after the swizzle — the swizzle moves whole 32-B tiles, so both the reader's `b128` loads and the K
writer's `uint4` store stayed wide stores at a swizzled, still-16-B-aligned address. A swizzle that had
broken the store width would show up here as `ds_store_b64`×2 and would be a bug, not a trade.

NOTE ON `tmp/a13/loops.py`
--------------------------
It is not a fourth ISA census tool and it does not re-derive one: `g3_isa_bill.py` does the span finding and
`a2_round_bill.py` does the bucketing. `loops.py` exists because for these two kernels the WIDEST backward
branch is not the round — knob 1's is 14,324 of 14,403 instructions and knob 2's is 17,431 of 17,610, both
swallowing the epilogue — so naming the round needed every backward branch listed with what it holds. It
prints the same buckets as `a2_round_bill.py` and no new classes. If this bill is kept, promote it into
`prototype/attn_percost/` beside `a2_round_bill.py` rather than leaving it in `tmp/`.
