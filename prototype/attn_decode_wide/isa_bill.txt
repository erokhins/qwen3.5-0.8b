# isa_bill.txt — the static per-loop instruction bill for both cores of this op.
# Made, from this directory, by:
#   python3 loop_bill.py attn_decode_wide.hip-hip-amdgcn-amd-amdhsa-gfx1151.s attn_core
#   python3 loop_bill.py attn_decode_wide.hip-hip-amdgcn-amd-amdhsa-gfx1151.s attn_core_lean
# CPU only: no device, no timing.
#
# READ EACH BLOCK AS AN UPPER BOUND ON ONE TRIP. A loop's bill is the instruction count of every basic
# block LLVM annotated as belonging to that loop. Blocks the geometry skips (`if (w < nt)`,
# `if (j == row_pos)`) are counted once per trip, so this is what a trip may issue, not what it does.
#
# THE CAVEAT THIS FILE USED TO CARRY, AND WHY IT IS GONE. Until the port (2026-10-21,
# PORT-D3-LEAN.md) the two cores' bills were NOT comparable, and the file said so: the shipped core's
# `nd`-bounded dot loops were rolled and left UNANNOTATED, so their bodies fell outside every annotated
# loop and its per-loop numbers under-counted — `fma32=1` inside BB0_69 was one rolled FMA standing for
# eight — while `attn_core_lean`, whose trip counts are literals, unrolled and billed completely
# (`fma32=17` in the same loop). That asymmetry was a property of the two SPELLINGS, not of the tool.
# The port put the literal-trip spelling into the shipping header, so both cores are now unrolled and
# both bills are complete, and comparing them means what it appears to mean: they are equal. The two
# blocks below are from one build of one header and agree loop for loop; the residual 3-instruction
# difference sits entirely outside the annotated loops and is unexamined (identical source text, so
# whatever it is, LLVM chose it, not the kernel).
#
# WHAT THAT DOES NOT BUY. A static bill is not a measurement, and the comparable facts were always the
# LDS reservation and the VGPR (`group_segment_fixed_size` 6,176 for both now, 38,944 for the shipped
# core before the port; `next_free_vgpr` 45 for both, 53 for the shipped core before). The pre-port
# record is kept verbatim underneath, because it is the evidence that the 226/137+118 figures quoted in
# `HANDOFF-D3.md` §1 and `results.md` were real — reading those numbers against THIS build would repeat
# the error AGENTS.md records as "a number taken from a file that has already corrected itself".
