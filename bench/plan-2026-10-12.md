## 0. Scope decisions (user, 2026-10-12) — these override everything below

| decision | value | consequence |
|---|---|---|
| concurrency | **single-stream only** | no batching, no `--serve`, no multi-request state design |
| quantization | **dropped** | bf16 stays the only weight path; all existing bands stay valid; no quantized-floor work |
| MTP (§09) | **dropped** | no draft kernels, no accept-rate plumbing, no MTP fixtures |
| context target | **4k** | block-parallel attention and removing `MAXSC = 512` become **required**, not optional |
| ship bar | **none for now** | no packaging, no HTTP endpoint, no corpus-G7 release gate |

Everything measurable is aimed at one number: **ms/token and time-to-first-token at a 4k context,
single stream, bf16, on this box.**

## 2. Queue

### Q1 — band option 1: route-spread-keyed allowance *(running, `edc7c407`)*
Gate step *j* on `1 − cos ≤ margin × measured_route_spread(j)` instead of the flat G5 floor, with the
margin **derived and reported even if inconvenient**, argmax agreement still hard underneath, the
allowance cached in the fixture manifest with its provenance, and a selftest proving it still
discriminates at a step flat-G5 passed. **If it does not go green, report the numbers — no tuning.**

### Q2 — Tier 1.1: engine G7 at breadth
Add breadth; the prompt rule below applies to every fixture here.

1. **Long-context forced-depth fixture**: ~300-token prompt **plus** ≥128 forced steps → lanes past 400,
   approaching the `MAXSC` cap. This turns split-block attention from hypothetical into required and
   exercises §07.3's online softmax at a lane count nothing has reached.
2. **Multi-turn chat fixture**: a transcript with a real assistant turn, covering second-turn state
   carry (cache across turns, the `feed`/`gen` session invariants `chat.sh` discovered by running).
3. **Free-run agreement depth measured on prose**: `dec64t`'s 64/64 was a deterministic counting chain
   and plainly lucky against A-18's ~4–8 token prediction. Re-measure on a prose prompt; report where
   divergence starts, wherever that is.
4. Per-step `cos`/`meanrel` curves on every new fixture — a drift-after-token-8 class bug (conv-window
   rollback) must not be able to hide.

**Acceptance:** each new fixture `--verify` byte-for-byte; `gate.py` runs it; curves in
`engine/results.md`; no band touched; disk budget respected (lean pin policy, ~60 MB/fixture).

### Q3 — Tier 1.2: police the bands
Wire `tools/band_history.py --check` into the gate path so a band edit without a recorded justification
fails. Acceptance: a deliberate band edit in a scratch worktree is caught; a normal gate run is unchanged.

### Q4 — Tier 1.3: close the audit debts
- `bench/gate-audit.md` rows still `NOT RUN` on device;
- §07.4 **position-64 pre-rope reduction** attribution (CPU-side: dump `z` post-`q_norm` pre-rope and diff
  against `specimpl.rmsnorm_zc` on the pinned row — answers "reduction order" vs "device libm");
- **lm_head G1 per-element rule** from the audit;
- cold weight-restore row (~1 s load) into the perf ledger (main agent runs the timing).

### Q5 — prefill (§06 / W7) + `MAXSC` removal — **the big one**
No prefill today: the prompt is fed one token per decode step, so a 27-token prompt costs ~320 ms before
the first word, and there is **no time-to-first-token figure at all**.

1. Implement §06 chunked prefill with its gate against the pinned prefill dumps (G3/G5 already define the
   invariants: incremental == batch).
2. Remove/raise `MAXSC = 512` via the block-parallel lane form §07.3 describes — required for the 4k
   target regardless, and prefill is what will cross it first.
3. Then measure and store, blocking and clean: prefill ms vs context (64 / 256 / 1024 / 3072) = TTFT curve;
   decode ms/token vs context including **1k and 4k** (the first honest long-context number).

**Acceptance:** G5 incremental==batch holds through the new path; `chat.sh` TTFT visibly drops; ledger
rows carry lock tag + spread.

### Q6 — Tier 3: single-stream performance, in this order
1. **Full-plan burst experiment** — 424 launches in dependency order, one sync at the end, compared to the
   engine's 11.919 ms. Decides which family the ~2.5 ms residue is in: serialized dispatch (≈237 launches
   × ~10 µs ≈ the residue) vs per-step sync + host work. Cheapest number that changes strategy.
2. **Launch-count reduction** — fold the 115 dtype casts into producers/consumers (48 of them are the MLP
   staging), widen block widths (`glue` 512 t ≫ 256/128), consider one fused small-op kernel per layer.
3. **Block-parallel attention for 4k** — mandatory at the chosen context target; 2.014 µs/lane extrapolates
   to ~50 tok/s at 4k. Price it first against a measured curve at 64/256/512/1024 lanes, not against the
   single slope.
4. **Narrow-shape projections** — `k_proj`/`v_proj` 40 %, `o_proj`/`out_proj` ~49 %, `in_proj_a`/`in_proj_b`
   **5 %**; this is what caps the family at 63–64 %. Shape problem, not tile problem.
5. **`proj_gemv --only gdn|attn` selector** + one clean timing run each, to fill ledger §2's two
   "not measured on their own" rows (they cannot be filled arithmetically — best-per-shape sums to 3.54 ms
   against the shipped plan's 3.081 ms).

## 3. Standing rules that bind every item

- **One subagent at a time**; the main agent owns every timing and every number that enters
  `bench/performance-status.md`; workers may run correctness-only device checks **under ~60 s** and must
  report command + wall time + `util` and say "no timing taken".
- **Never loosen a gate to make it pass.** Bands are derived from measured floors; a new constant needs a
  floor probe.
- **Device measurements blocking, zero subagents**, spread stated, `util` discounted; do not hold
  `gpu_lock.sh` when running `glue` / `proj_gemv` / `gdn_gated_norm` — they self-lock and will park.
- **Never write chat-template special tokens literally** anywhere — refer to them by id (248046 eos;
  248068/248069 think-boundary). This has truncated agent messages and a worker brief.
- **Deep-fixture prompt rule**: the prompt must actually generate many tokens — pre-flight with
  `tools/stop_probe.py`, require no stop id across the whole intended generation (≥128 target, ≥80 before
  pinning), and record the first-stop index in the manifest. Known-good, no stop within 120: count-1-to-80
  (`dec64t`), 200-word Paris paragraph, months-and-lengths list, bicycle explanation, prime continuation.
- **Pin with teacher forcing for depth** — free-run id parity beyond ~8 tokens is A-18 territory and will
  fail for correct code.
- Commit by topic with explicit pathspecs; commit WIP rather than lose it.
